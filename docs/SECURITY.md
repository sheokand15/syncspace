# Security

Identity must be server validated. Store only password hashes if local credentials are used; sessions use random opaque identifiers stored hashed in the database, HttpOnly cookies, appropriate SameSite/Secure attributes, expiry, and CSRF checks for mutations. Every HTTP document operation and WebSocket room join checks current workspace/document membership and permission. Read-only clients cannot submit Yjs update messages. Share changes and document deletion close active sockets for affected users; clients must reconnect and reauthorize. Existing sockets are not continuously polled against the database, so revocation takes effect when the owner performs the access change and the service closes the tracked connection.

Validate HTTP and custom messages with Zod, cap payloads and connections, validate WebSocket origins, and rate-limit authentication and connection attempts. Use parameterized SQL, least-privilege database credentials, encrypted backups, managed secrets, and dependency updates. Logs may include request IDs and metadata but not passwords, session tokens, or document bodies. Known limitations must be updated as the implementation matures; client route guards are never an authorization boundary.
