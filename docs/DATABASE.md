# Database Design

The PostgreSQL schema keeps password hashes in the application user table because local registration is implemented. Tables: `users(id,email,name,password_hash,created_at)`, `sessions(id,user_id,csrf_token,expires_at,created_at)`, `workspaces(id,name,owner_id,created_at,updated_at)`, `workspace_members(workspace_id,user_id,role,joined_at)`, `documents(id,workspace_id,created_by,title,snapshot_version,created_at,updated_at,deleted_at)`, `document_members(document_id,user_id,permission,created_at)`, `document_updates(id,document_id,sequence,update_bytes,created_at)`, and `document_snapshots(id,document_id,state_bytes,covered_sequence,created_at)`. `schema_migrations` records applied SQL migration filenames.

Use UUID primary keys, foreign keys with cascades for dependent membership/update rows, unique normalized email and membership pairs, checks for roles/permissions, and indexes on workspace/document membership, recent documents, and `(document_id,sequence)`. Updates are binary and parameterized. Each edit update is appended in a transaction before it is applied to the room or relayed. Cursor movements are never persisted.

Recovery loads latest snapshot and replays updates whose sequence exceeds its checkpoint. Appends allocate sequence transactionally per document. Compaction runs in the per-room persistence queue, locks the document checkpoint, captures state through sequence N, inserts snapshot N and prunes only `sequence <= N` in one transaction; later updates remain replayable. Back up with managed point-in-time recovery or encrypted `pg_dump`; restoration must be rehearsed. Connection pooling is bounded. Retention keeps one or more recent snapshots plus uncovered updates; deletion/retention policy must account for user expectations. The schema and recovery path have not yet been validated against a live PostgreSQL instance.

Executable migrations live under `database/migrations/`; migration application is ordered and recorded, and schema changes are additive where possible. The actual schema must be updated here when migrations are added.
