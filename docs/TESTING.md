# Testing Strategy

Use Vitest for pure functions, validation, permission decisions, persistence/recovery, and deterministic Yjs merge tests; API integration tests use a disposable PostgreSQL database; WebSocket tests use independent Yjs clients and the actual provider; Playwright uses two isolated contexts and deterministic users. Verify denial for private-document access and read-only update attempts. Exercise duplicate/out-of-order Yjs updates, concurrent insertions and formatting, reconnect after missed updates, and server restart recovery. `apps/server/src/crdt.test.ts` covers independent concurrent edits, duplicate/out-of-order delivery, offline merge, and checkpoint replay; it does not substitute for provider/PostgreSQL integration tests.

Offline tests disconnect transport, make edits while IndexedDB is active, reconnect, and assert all replicas converge and content survives refresh. Persistence tests wait for commit before stopping the service and verify recovery. Snapshot tests race compaction with new appends and assert no update loss. Failure cases include DB outage, revoked membership, and expired sessions.

Pass criteria: independent replicas have equal Yjs state vectors/content after synchronization; unauthorized reads/writes are rejected; committed content survives process restart; offline pending edits merge with remote edits without replacing them. Benchmarks use fixed seeds, documented workload/runtime, and report measured p50/p95/p99 only when sample counts support them. Local prerequisites and runnable commands will be recorded after tooling is installed; no test is considered passed until executed.
